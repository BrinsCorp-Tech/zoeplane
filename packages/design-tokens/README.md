# @zoeplane/design-tokens

Design token pipeline: DTCG JSON source → Style Dictionary v4 → `tokens.css` + `tokens.d.ts`

## Pipeline overview

```
Figma Variables (designer-authored)
        │
        ▼
Token Studio (DTCG JSON export)
        │
        ▼
  src/tokens.seed.json   ← canonical machine-readable spec (DTCG W3C v1 format)
        │
   Style Dictionary v4
        │
        ├── ../../src/styles/tokens.css   ← consumed by Tailwind v4 @theme + host CSS
        └── dist/tokens.d.ts              ← TypeScript types for plugin SDK consumers
```

## During Sprint 1 (scaffold phase)

`src/styles/tokens.css` is the **hand-authored canonical source**. The seed JSON in this
package mirrors it for pipeline setup purposes.

Once the Style Dictionary pipeline is active (Sprint 1 story: "Design token pipeline"),
`tokens.css` becomes a BUILD ARTIFACT — it is generated by `bun run build` in this package.
At that point, **do not hand-edit tokens.css** — edit the DTCG JSON source instead.

## Style Dictionary v4 build

```bash
# From repo root
bun run --cwd packages/design-tokens build

# Or directly
cd packages/design-tokens
bun run build
```

This outputs:
- `../../src/styles/tokens.css` — the compiled CSS custom properties
- `dist/tokens.d.ts` — TypeScript type definitions for plugin authors

## Token completeness check

CI runs `bun run check-tokens` on every PR that touches `tokens.css`. This script
verifies that every semantic token declared in `:root[data-theme="light"]` also
exists in `:root[data-theme="dark"]`. Mismatched sets fail the build.

The check script lives at `scripts/check-token-completeness.mjs`.

## DTCG format reference

W3C Design Tokens Community Group: https://design-tokens.github.io/community-group/format/

Every token uses `{ "$value": "...", "$type": "color" }` shape.
Nested groups are written as `{ "groupName": { "tokenName": { "$value": "..." } } }`.
