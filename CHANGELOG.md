## [Unreleased]

### Sprint 2 (2026-05-11 → 2026-05-15)

Sprint 2 delivered the complete design system foundation: a DTCG W3C v1 three-tier token architecture with OKLCH primitives, 16 foundation-tier and 9 layout-tier UI components, the HostShell composition root, a 41-animation catalog, WCAG 2.2 AA contrast enforcement, and per-component axe-core structural accessibility tests. Infrastructure additions include a reusable CI build-matrix workflow, Chromatic visual regression in advisory mode, PostCSS configuration consolidation, and `Cargo.lock` policy resolution. Locked by ADR-004 (Design System Architecture).

#### Added

- **Design token pipeline** (PRs #13, #14 — Stories 2.1, 2.5): `packages/design-tokens/src/tokens.seed.json` (DTCG W3C v1 format) as the single source of truth for all color primitives and motion values. Style Dictionary v4 pipeline at `packages/design-tokens/style-dictionary.config.mjs` with a custom `zoeplaneTokensCSS` formatter. Output: `src/styles/tokens.css` (gitignored build artifact). Build command: `bun run tokens:build`. Validation: `bun run tokens:check` (rebuilds + asserts non-empty). Husky pre-commit hook blocks direct edits to `tokens.css`.
- **Three-tier token architecture** (PRs #13, #14 — Stories 2.1, 2.5, ADR-004): Layer 1 (primitives, theme-invariant, OKLCH color space) → Layer 2 (semantic, only layer that branches on `[data-theme]`) → Layer 3 (component, theme-invariant references to semantic). Additional theme-invariant layers: typography (fluid type scale via `clamp()`), spacing (4px base), shape (radii + shadows), motion (duration + easing), layout (breakpoints). OKLCH primitives cover: gray ramp (13 steps), accent hue 260 (8 steps), success/warn/danger/info/quarantine status ramps, 4 event-family hue groups (tool/session/prompt/compact).
- **ThemeProvider** (PR #14 — Story 2.5): `src/components/theme/ThemeProvider.tsx` — manages `light | dark | system` preference with FOUC prevention (inline `<script>` before React mount), `localStorage` persistence (`key: "zoeplane:theme"`), OS `matchMedia` subscription, `useLayoutEffect`-based `data-theme` attribute writes. `useTheme()` hook exported for settings controls only — not for component branching (no-theme-branch rule per ADR-004).
- **shadcn/ui scaffold** (PR #14 — Story 2.5): shadcn/ui configured as a copied-and-owned pattern (not a dependency). Tailwind v4 consuming design tokens via CSS custom properties. PostCSS at project root `postcss.config.js` with `@config` directive pointing at `tailwind.config.ts`.
- **Foundation tier — 16 P0 components** (PRs #14, #15, #16 — Stories 2.5, 2.6): All at `src/components/ui/`. Button (6 variants, `cva`, loading/disabled states, `aria-busy` + `aria-disabled` pattern), Card (CardHeader/CardContent/CardFooter), Badge (7 semantic variants), Input (text/email/search), Icon (Lucide wrapper, size system), Modal (Radix Dialog), Toast + Toaster (Radix Toast), Tooltip (Radix Tooltip), Dropdown (Radix DropdownMenu), FormField (label+input grouper, `groupRole` extension for radio/checkbox sets), Select (Radix Select), Checkbox (Radix Checkbox), Radio (Radix RadioGroup), Tabs (Radix Tabs), Skeleton (+ CardSkeleton/RouteSkeleton/StreamSkeleton variants), Spinner (4 sizes). Top-level barrel: `src/components/ui/index.ts`. All components zero hardcoded hex values (audit-verified).
- **EvaluatorStatusBadge** (PR #15 — Story 2.7): `src/components/ui/EvaluatorStatusBadge/EvaluatorStatusBadge.tsx` — 16-state status matrix for the Skill Safety Evaluator. Type signature frozen for Epic 04 integration.
- **Layout tier — 9 P0 regions** (PRs #16, #18 — Stories 2.8, 2.9, 2.10, 2.11): Sidebar (role="navigation", CollapsiblePane primitive), Inspector (role="complementary", CollapsiblePane, `expandedWidth` prop), TitleBar (role="banner", drag-region, macOS traffic-light zone), StatusBar (role="contentinfo", sidecar health poll at configurable interval), TabStrip (Zustand-managed), PrimaryWorkArea (flex: 1, scrollable), CommandPalette (Cmd+K palette, Radix Dialog portal), NotificationsCenter (right-edge dialog portal). CollapsiblePane (`src/components/layout/CollapsiblePane/`) is a cross-cutting collapse primitive used by both Sidebar and Inspector.
- **HostShell composition root** (PR #16 — Story 2.8): `src/components/layout/HostShell/HostShell.tsx` — CSS Grid compositor (3-row × 3-column: `"title title title" / "sidebar content inspector" / "status status status"`, column widths `240px 1fr 320px`). Replaces Sprint 1 `PageLayout.tsx` and `SectionLayout.tsx` scaffold. CommandPalette and NotificationsCenter mount as portal siblings outside the grid.
- **LibraryShell** (PR #18 — Story 2.11): `src/components/library-shell/LibraryShell.tsx` — cross-library card-grid primitive for catalogue views.
- **Animation library** (PR #20 — Story 2.12): `src/styles/animations.css` — 41 named animation classes (A-01..A-41). Each class consumes motion tokens (`var(--motion-duration-*)`, `var(--motion-easing-*)`). Every infinite-loop animation carries an explicit `.prefers-reduced-motion .X { animation: none }` override in the class-based fallback block. Storybook catalog at `src/styles/Animations.stories.tsx`.
- **Motion tokens** (PR #20 — Story 2.12): 6 DTCG tokens added to `tokens.seed.json` — `motion.duration.{fast,base,slow}` (120 ms / 200 ms / 400 ms) and `motion.easing.{standard,decelerate,accelerate}`. Global reduced-motion block in `src/styles/globals.css` zeros `animation-duration` + `transition-duration` across the full document via `@media (prefers-reduced-motion: reduce)`.
- **Storybook 8 + global decorators** (PR #13 — Story 2.4): `.storybook/main.ts` + `.storybook/preview.ts`. Global decorators: theme toggle (light/dark) and reduced-motion toggle. All 25 components + animation catalog have Storybook stories.
- **Chromatic visual regression** (PR #13 — Story 2.4): `.github/workflows/chromatic.yml` — runs on PR and push to `main`/`develop`. Advisory mode (`exitZeroOnChanges: true`). All steps skip gracefully when `CHROMATIC_PROJECT_TOKEN` GHA secret is absent. TurboSnap (`onlyChanged: true`). Baseline lock procedure documented in `docs/runbooks/chromatic-baseline-lock.md`.
- **WCAG 2.2 AA contrast harness** (PR #21 — Story 2.13): `src/test/contrast-harness.a11y.test.ts` — validates 26 semantic token pairs × both themes using `culori v4` `wcagContrast()` (OKLCH-native math). Thresholds: ≥ 4.5:1 body text, ≥ 3.0:1 large text + non-text UI. AAA (≥ 7.0:1) gaps logged but do not fail the suite. Script: `bun run test:contrast`.
- **Per-component axe-core accessibility tests** (PRs #15, #16, #18 — Stories 2.6, 2.7, 2.8, 2.9, 2.10, 2.11): 28 `*.a11y.test.tsx` files (16 foundation + 11 layout + LibraryShell + EvaluatorStatusBadge) using vitest + `axe-core`. Canonical helper: `src/test/helpers/runAxe.ts` (exports `runAxe`, `runAxeBody`, `formatViolations`). `color-contrast` axe rule disabled in JSDOM (OKLCH limitation); contrast is validated separately by the contrast harness.
- **Zustand state management** (PRs #16, #18 — Stories 2.8, 2.9, 2.10): `src/stores/app.ts` (shell readiness + `projectRoot` + TabStrip slices), `src/stores/notifications.ts` (notification queue), `src/stores/commandPalette.ts` (palette state + query). `project-open` event shape exported from `packages/shared-types`.
- **Reusable CI build-matrix workflow** (PR #13 — Story 2.2): `.github/workflows/_build-matrix.yml` — extracts the duplicated lint/typecheck/test/build matrix from `ci.yml` and `nightly.yml` into a single `workflow_call` reusable workflow. Resolves Sprint 1 MED-3 carryover.
- **`design-tokens-check` CI job** (PR #13 — Story 2.3): Validates the token build pipeline on every PR — runs `bun run tokens:build` and asserts non-empty `tokens.css` output. Catches `tokens.seed.json` syntax errors and Style Dictionary formatter regressions before merge.
- **Cargo.lock committed** (PR #13 — Story 2.3): `src-tauri/Cargo.lock` is now tracked in git. Binary-crate convention: committing Cargo.lock gives reproducible dependency resolution across developer workstations and CI. Resolves Sprint 2 policy decision from SPRINT-2-CARRYOVERS.md.
- **ADR-004** (2026-05-11): Design System Architecture. Locks DTCG three-tier cascade, OKLCH primitives, Style Dictionary v4, shadcn/ui scaffold pattern, Storybook 8 + Chromatic advisory mode, no-theme-branch-in-component invariant, and semantic equivalence proof requirement for `tokens.css` migration. See `docs/architecture/decisions/README.md`.

#### Changed

- **PostCSS configuration consolidated** (PR #24 — Story 2.22): Deleted `src/postcss.config.js` (Sprint 1 duplicate). Single canonical PostCSS config now lives at project root `postcss.config.js`. `src/vite.config.ts` updated to point at the root config explicitly. Resolves Sprint 2 carryover from PR #18.
- **DEV-mode Zustand store exposure** (PR #24 — Story 2.22): `src/main.tsx` exposes `useAppStore`, `useCommandPaletteStore`, `useNotificationsStore` on `window` via `Object.assign` under `import.meta.env.DEV` guard. Tree-shaken from production builds. Enables devtools-driven smoke testing without a dedicated DevTools panel.

#### Fixed

- **Smoke-test infrastructure** (PR #18 — post-Story 2.6 Batch F amendment): Four latent scaffold bugs surfaced by manual visual smoke testing: PostCSS plugin not discovered by Vite (root config was absent), `@config` directive missing (Tailwind JS config not auto-loaded in v4), unlayered CSS reset overriding `@layer utilities` rules, Modal missing `display: flex` on its content wrapper causing invisible-but-present modal. All four fixed in a single commit (`e00f4cd`).
- **Dead re-exports removed** (PR #24 — Story 2.24): 13 dead `export default <Name>;` lines removed from foundation-tier components. `src/components/ui/Skeleton/index.ts` and `src/components/ui/EvaluatorStatusBadge/index.ts` deleted (superseded by top-level barrel). All consumers updated to named imports from `src/components/ui/index.ts`.
- **Scaffold layout removed** (PR #24 — Story 2.25): `src/components/layout/PageLayout.tsx` and `src/components/layout/SectionLayout.tsx` deleted. These Sprint 1 placeholder layouts are fully superseded by HostShell. All references updated.
- **Contrast harness execution order** (PR #24 — Story 2.26 amendment): `aaaResults` accumulator moved to outer-describe scope + `afterAll` for execution-order robustness. Prevents a race condition where `aaaResults` could be read before all `it()` blocks had run when the vitest scheduler ran them out of declaration order.
- **`success-600` token darkened** (PR #21 — Story 2.13 in-sprint correction): `color.success.600` in `tokens.seed.json` changed from `oklch(0.560 0.170 150)` to `oklch(0.540 0.170 150)` to clear the WCAG AA 4.5:1 threshold for the `--color-success` / white foreground pair (ratio improved from 4.32:1 to 4.69:1).

### Sprint 1 (2026-05-07 → 2026-05-09)

Sprint 1 established the foundational monorepo scaffold, the Tauri shell and sidecar lifecycle, SQLite migration infrastructure, CI/release pipeline, code-signing pipeline, the Plugin SDK public contract, and the policy bundle (pre-commit hooks, FS allowlist enforcement, deep-link registration). No signed release has been tagged yet; the first tag will be `v0.1.0` once 10 GHA secrets are provisioned.

#### Added

- **Monorepo scaffold** (PR #1 — Story 1.1): Bun workspaces with packages `src` (React/Vite/Tailwind v4 UI), `sidecar` (Node.js bun-compiled single-binary), `packages/plugin-sdk` (`@zoeplane/plugin-sdk`), `packages/shared-types` (`@zoeplane/shared-types`), `packages/design-tokens` (DTCG → Style Dictionary v4 pipeline). `package.json` workspace root at version `0.1.0`, `src-tauri/Cargo.toml` at version `0.1.0`.
- **Tauri Rust shell core** (PR #1 — Story 1.1): `src-tauri/src/lib.rs` with structured tracing (via `tracing` + `tracing-subscriber`), app window configuration (1280×800, min 1024×720), plugin registration (`tauri-plugin-shell`, `tauri-plugin-fs`, `tauri-plugin-dialog`, `tauri-plugin-notification`, `tauri-plugin-process`, `tauri-plugin-deep-link`).
- **Sidecar lifecycle** (PR #3 — Story 1.2): `spawn_sidecar()` in `lib.rs` resolves `appDataDir()` using the bundle identifier, passes `--db-path` and `--migrations-dir` to the sidecar at spawn, supervises the process via `CommandEvent` channel, and emits `sidecar-ready` to the UI on port announcement. Clean shutdown on `WindowEvent::CloseRequested` and `RunEvent::Exit`.
- **HTTP loopback IPC** (PR #3 — Story 1.2): Sidecar binds `Bun.serve` to `127.0.0.1:0` (kernel-assigned ephemeral port), announces bound port via stdout as `{"port": N}`. Tauri shell captures port and stores in `SidecarPort` app state. `sidecar_status` Tauri command issues `GET /health` with a 100 ms timeout (`ipc.rs`).
- **Sidecar structured logging** (PR #9 — Story 1.9 amendment): `sidecar/src/log.ts` — `log(level, message, extra?)` writes `JSON.stringify({ level, message, pid, ...extra })` to stderr. Every sidecar log line includes `pid` for restart correlation.
- **SQLite migration runner** (PR #4 — Story 1.3): `sidecar/src/db/runner.ts` — forward-only migration runner using `bun:sqlite`. Bootstraps `__migrations` tracking table, discovers `NNN_description.sql` files, applies pending migrations in ascending numeric order inside individual transactions. Fatal on migration failure (exit code 1). Supports `--migrations-dir` production path and dev fallback.
- **Migration 001** (PR #4 — Story 1.3): `sidecar/src/db/migrations/001_init.sql` creates `__migrations` table (idempotent). First and only domain-layer migration in Sprint 1.
- **CI matrix pipeline** (PR #5 — Story 1.4): `.github/workflows/ci.yml` — lint + typecheck + test + scaffold-health + actionlint + build (unsigned) across `macos-latest`, `windows-latest`, `ubuntu-22.04`. `fail-fast: false`. Results table written to GHA step summary. ESLint 9 flat config (`eslint.config.js`).
- **Nightly pipeline** (PR #5 — Story 1.4): `.github/workflows/nightly.yml` — same matrix as CI, runs daily at 07:00 UTC against `main`, plus manual dispatch.
- **Code-signing release pipeline** (PR #6 — Story 1.5): `.github/workflows/release.yml` — triggered by `v*.*.*` semver tags. Three parallel platform jobs: macOS (universal-apple-darwin, Apple Developer ID codesign + notarization via `xcrun notarytool`), Windows (Authenticode via `.pfx` + `signtool.exe`), Linux (GPG via AppImageTool with `APPIMAGETOOL_FORCE_SIGN=1`). All jobs validate required secrets before spending build time and fail loudly on absent secrets. GitHub Release draft published by `tauri-apps/tauri-action@v0`.
- **Plugin SDK** (PR #7 — Story 1.6): `packages/plugin-sdk/src/index.ts` — `@zoeplane/plugin-sdk@0.0.1`. Exports `PluginManifest`, `PluginCapabilities`, `PluginExtensionPoints` (navigation, view, run-stream observer, resource enricher, settings panel), `ZoePlaneHostBridge`, and `HostEventType`. All APIs marked `@experimental`; runtime implementation is Epic 04.
- **Plugin SDK publish pipeline** (PR #7 — Story 1.6): `.github/workflows/publish-sdk.yml` — fires on same `v*.*.*` tag as `release.yml`. Builds via `tsup`, verifies `NPM_TOKEN` secret, publishes `@zoeplane/plugin-sdk` to npm as public. Fails loudly if `NPM_TOKEN` is absent.
- **Homebrew Cask stub** (PR #7 — Story 1.6): `packaging/homebrew/zoeplane.rb` — static stub for `brinscorp-tech/homebrew-zoeplane` tap. Version and SHA256 placeholders require per-release operator update. Depends on macOS ≥ 13 (Ventura). Declares `zap trash` paths targeting `com.brinscorp.zoeplane`.
- **Winget manifest stubs** (PR #7 — Story 1.6): `packaging/winget/BrinsCorpTech.ZoePlane/` — three winget manifests (version, locale, installer) at schema 1.9.0. Submission to `microsoft/winget-pkgs` is post-Sprint-1.
- **Pre-commit policy** (PR #8 — Story 1.7): Husky 9.1.7 pre-commit hook via `prepare` script. lint-staged runs ESLint `--fix` + Prettier `--write` on staged TypeScript files, and Prettier on JSON/Markdown/CSS/HTML. Hook config in root `package.json:lint-staged`.
- **Deep-link registration** (PR #8 — Story 1.7): `zoeplane://` URL scheme registered via `tauri-plugin-deep-link` in `tauri.conf.json`. `lib.rs:108-133` handler validates scheme and structure, logs at WARN for unexpected/malformed URLs, does not crash. Action dispatch is Epic 10.
- **FS allowlist enforcement** (PR #8 + PR #9 — Stories 1.7 + 1.8): `src-tauri/src/commands/fs.rs` — four Tauri IPC commands (`fs_read_file`, `fs_write_file`, `fs_read_dir`, `fs_exists`) each performing an upfront `app.fs_scope().is_allowed()` check. Scope denials trigger `log_violation()` which emits a structured ERROR on the `fs-allowlist` tracing target and a JSON line on `fs-allowlist-json`. ESLint rule prohibits direct `@tauri-apps/plugin-fs` usage in the React UI.
- **ADR-001** (2026-05-09): Retains `com.brinscorp.zoeplane` as the permanent bundle identifier. See `docs/architecture/decisions/ADR-001-bundle-identifier.md`.
- **Public OSS policy documents** (PR #8 — Story 1.7): `LICENSE` (Apache 2.0), `NOTICE` (third-party attributions), `CONTRIBUTING.md` (contributor guide including FB-016 enforcement details and branch naming conventions).
- **Founding documentation** (Sprint 1 close): `docs/ARCHITECTURE.md`, `docs/INSTALL.md`, `docs/SECURITY.md`, `docs/CONFIGURATION.md`, `docs/BUILD-AND-RELEASE.md`, `docs/IPC-API.md`, `docs/PLUGIN-SDK.md`, `docs/DATA-MODEL.md`.

#### Fixed

- **CI YAML** (PR #2 — hotfix): Corrected GitHub Actions workflow YAML syntax error introduced in the initial monorepo commit. CI matrix was non-functional until this fix.
- **`tauri-plugin-fs` API usage** (PR #8 build-matrix fix commit `87b73af`): Corrected `tauri-plugin-fs` API calls in `src-tauri/src/commands/fs.rs` to use `FsExt` trait methods correctly for Tauri 2.0 compatibility. PR #8 had failed on Windows and Linux matrix legs due to this API mismatch.
- **IPC hygiene** (PR #9 — Story 1.8 amendment): Resolved a dual-emission issue in `log_violation` where the structured tracing event and the JSON stderr line could produce inconsistent field sets under certain log configurations. (MED-1 from code-audit pass 2; a residual dual-emission cleanup is tracked for Sprint 2.)
- **Sidecar scope consolidation** (PR #9 — Story 1.10 amendment): Consolidated FS scope-deny logic across the four `commands/fs.rs` wrappers into a consistent pattern — all four now perform the `is_allowed` check at the same structural position before any I/O.
- **Tauri 2.x permission migration** (Story 1.11 amendment — 2026-05-10): Migrated `tauri.conf.json` from Tauri 1.x plugin-permission schema to the Tauri 2.x capability model (ADR-002). Removed `"all"` field and all method-permission boolean keys from `plugins.shell` and `plugins.fs` (the 1.x schema caused a runtime panic on plugin deserialization — the app had never successfully booted from source). Created `src-tauri/capabilities/default.json` granting 12 enumerated capability identifiers scoped to the `main` window. Set `plugins.shell.open: false` (Tauri 2.x rejects `true`; URL-open is not a Sprint 1 use case).
- **AppData directory bootstrap** (Story 1.11 amendment — 2026-05-10): Added `std::fs::create_dir_all(&app_data_dir)` to `lib.rs::spawn_sidecar` before the `db_path` join. On a fresh user account or post-clean-state run, the AppData directory now exists before the sidecar is spawned, preventing SQLite from failing to open a file in a non-existent directory. Structured logging added on success (`tracing::info!` with `dir_created: true`) and on failure (`tracing::error!` with the underlying I/O error). Rust unit test covers the bootstrap path.
- **Vite mobile-scaffold cleanup** (Story 1.11 amendment — 2026-05-10): Removed `internal-ip` import and LAN-IP binding from `src/vite.config.ts` (copied from a Tauri mobile scaffold template). Vite now binds exclusively to `localhost:5173`. Removed `internal-ip` from `package.json` devDependencies.
- **Developer-prerequisites documentation** (Story 1.11 amendment — 2026-05-10): Added `cargo install tauri-cli --version "^2" --locked` to `docs/INSTALL.md` build-from-source section and `CONTRIBUTING.md`. Added "Clean-state smoke testing" subsection to `CONTRIBUTING.md` documenting `scripts/clean-state.sh` and the clean-state verification workflow. Added `scripts/clean-state.sh` (macOS, mode 0755, idempotent) that wipes the four `com.brinscorp.zoeplane` platform-state locations for reliable clean-state boot verification.
- **Tauri 2.x FS runtime scope initialization** (Story 1.12 amendment — 2026-05-10): Populated `app.fs_scope()` programmatically at app setup via `allow_directory` calls for the three canonical allowlist paths, resolving variable prefixes through `app.path()` to guarantee physical-path equivalence with the capability file's scope entries. Removed the stale `plugins.fs.scope` block from `tauri.conf.json` (the 1.x `scope` array is rejected at runtime by the 2.x `tauri-plugin-fs` schema — only `requireLiteralLeadingDot` is valid configuration; path scope now lives in `capabilities/default.json` + runtime `lib.rs::setup`). Added ancestor-probe logic to all four `commands/fs.rs` wrappers so that nonexistent-but-in-allowlist paths (e.g., a file not yet written) return `Ok(false)` from `fs_exists` and pass the scope check for `fs_write_file` rather than triggering a spurious violation log. Enabled `app.withGlobalTauri: true` as a Sprint 1 dev-ergonomics setting (scheduled revert before v0.1.0-alpha — see Sprint 2 carryovers). Added `fs-scope-init` structured tracing target (INFO on boot listing registered paths; ERROR on initialization failure). Added `init_fs_scope` extracted helper function (called from both production setup and the new integration test). New Rust integration test using Tauri's `MockRuntime` (Tier 2 extracted-helper approach) asserts all three canonical paths are `is_allowed` after setup, one out-of-scope path is denied, and at least one `fs-scope-init` INFO log entry is emitted. Defense-in-depth scope check in `commands/fs.rs` now functions correctly for in-allowlist paths (pre-1.12, `app.fs_scope()` was empty, causing every path including `~/.claude/CLAUDE.md` to return `Err("path not allowed")`). Formalized by **ADR-003** (Tauri 2.x Runtime Scope vs. Capability Scope), which partially supersedes ADR-002 invariant 4.
